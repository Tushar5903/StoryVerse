# AGENTS.md

Two independent apps in this repo:

- `StoryVerse/` — Spring Boot 3.5.16 REST backend (Java 21, Maven, package `com.storyreview`, main class `StoryReviewApplication`)
- `FRONTEND/` — React 19 + Vite 8 + Redux Toolkit + react-router 7 + framer-motion + swiper + lucide-react (plain JS, no TS)

## Commands

Backend (run in `StoryVerse/`):
- Dev server: `.\mvnw.cmd spring-boot:run` (Windows) or `./mvnw spring-boot:run`
- Tests: `.\mvnw.cmd test` — only 2 tests; `JwtServiceTest` is pure unit, `StoryVerseApplicationTests` loads the context and fails without MySQL

Frontend (run in `FRONTEND/`):
- Dev server: `npm run dev`
- Lint: `npm run lint` (ESLint flat config, `eslint .`)
- Build: `npm run build`
- No frontend test framework.

## Backend gotchas

- Serves on port **8082** (`${SERVER_PORT:8082}`), not 8080; API base path is `/api`. Swagger UI at `/swagger-ui.html`.
- Requires a running MySQL at `jdbc:mysql://127.0.0.1:3306/storyverse_db` (user/password come from the gitignored `StoryVerse/.env` — `DB_USERNAME`/`DB_PASSWORD`).
- `spring.jpa.hibernate.ddl-auto=validate` + Flyway enabled (`classpath:db/migration`, migrations V1–V10): schema changes MUST be a new `V11__*.sql` migration, never rely on JPA DDL. V9 (`V9__add_user_profile_fields.sql`) added `users.date_of_birth`, `users.instagram`, `users.twitter`, `users.youtube` (all nullable) — note the old contact-messages V9 was deleted and its Flyway history row purged, so that version number was reused. V10 (`V10__otp_codes.sql`) added the `otp_codes` table for registration OTPs.
- Registration is **OTP-gated** (no direct user-creation endpoint): `POST /api/auth/register/send-otp` (Bean Validation runs first, email/username uniqueness → 409, 6-digit code emailed, TTL from `app.security.otp.ttl-seconds` default 300s; **resend invalidates prior unused codes** for that email, SMTP failures are logged and swallowed like forgot-password) then `POST /api/auth/register/verify` (full `RegisterRequest` + `otp`; invalid/used/expired code → 400, uniqueness re-checked → 409, creates user `enabled+emailVerified=true` **with role always `USER`** — the register DTOs have **no `role` field** and `AuthServiceImpl.verifyRegistration` hardcodes `Role.USER`; never reintroduce client-supplied roles, that would allow privilege escalation). Returns `AuthResponse` so the frontend **auto-logs-in**. The old `/auth/register` was removed — never reintroduce a registration path that skips OTP. Frontend: `authApi.js` `sendRegistrationOtp`/`verifyRegistrationOtp` (verify uses `saveAuth`); the 2-step UI (form → code + 5-min countdown + resend) lives in the inline `Auth` component in `App.jsx`.
- Secrets are NOT in version control: `application.properties`/`application-test.properties` use bare placeholders (`${DB_PASSWORD}`, `${JWT_SECRET}`, `${MAIL_*}`, `${CLOUDINARY_*}`) and `spring.config.import=optional:file:.env[.properties]` loads the gitignored `StoryVerse/.env` (real OS env vars override it). `application-example.properties` documents the variables. Never hardcode a secret, and never commit `.env` or `application.properties`. Env-overridable via `MAIL_*`, `CLOUDINARY_*`, `JWT_SECRET`, `DB_PASSWORD`, etc. Don't introduce new hardcoded secrets.
- Security: stateless JWT; `/api/auth/**`, swagger, actuator health, GET `/api/authors*`, `/api/books*`, `/api/users/*`, `/api/health`, GET `/api/books/*/chapters*`, and GET `/api/reviews` are public — everything else requires `Authorization: Bearer`. Chapter reads of *draft* books 404 for non-owners; review reads of drafts return an empty page — except the book's owner or an admin, who pass `@AuthenticationPrincipal CurrentUser` (nullable) through the service and get access (same pattern in `ChapterServiceImpl.assertReadable`). Admin endpoints (`/api/admin/**` class-level, `AuthorController` POST/PUT, `BookController` POST `/books/review`, `UploadController` `/upload/author-image`) are `@PreAuthorize("hasRole('ADMIN')")` and return 403 JSON via `RestAccessDeniedHandler` — never weaken these; admin routes in the frontend must use the `RequireAdmin` guard (App.jsx), not `RequireAuth`.
- Book genres are a fixed set of 22 (`BookGenre` enum: Action, Adventure, Biography, Business, Children's Books, Comedy, Crime, Drama, Fantasy, Historical Fiction, History, Horror, Informative, Mystery, Poetry, Romance, Science Fiction, Self-Help, Sports, Technology, Thriller, Young Adult). Books support **multiple genres**: stored in the `book_genres` element-collection table (V8 migration replaced the old single `books.genre` column, backfilling "Sci-Fi" → "Science Fiction" via a `BookGenre.ALIASES` map — keep that alias if you rename genres again). Request DTOs take `genres` (Set), validated/normalized via `BookGenre.normalizeAll`; `BookResponse` carries `genres` plus a `genre` convenience field (first/primary genre) that all the display code still reads. The catalog filter (`GET /api/books?genre=`) matches ANY of a book's genres (`isMember` spec, unknown values fall through to an empty result, not a 400). Expose the list via `GET /api/books/genres`. Frontend list lives in `src/data/genres.js` (`DEFAULT_GENRES`) — keep it in sync with the enum; the editor's multi-select chips, GenrePage tiles, and genre-path routes all derive from it.

## Backend conventions

- Service layer: `XxxService` interface + `XxxServiceImpl` in `service/impl/`.
- Response DTOs are Java records added to the single `dto/response/ApiResponses.java` class (not one file per response); request DTOs are grouped per-domain in `dto/request/XxxRequests.java`.
- Auth/roles via `@EnableMethodSecurity`; uploads go through Cloudinary (`UploadController`, 10MB multipart cap).
- Reading progress: `ProgressService`/`ProgressServiceImpl` + `ReadingProgressRepository`; endpoints `POST /api/progress`, `DELETE /api/progress/{chapterId}`, `GET /api/progress`, `GET /api/progress/book/{bookId}`.
- `GET /api/users/{identifier}` resolves a user by id *or* username.
- User profile extras: `PUT /api/users/me` (multipart) accepts `name`, `bio`, `dateOfBirth` (ISO `YYYY-MM-DD`, blank clears), `instagram`, `twitter`, `youtube`, `image`; both `UserResponse` and `PublicUserResponse` carry the social/DOB fields; DOB is private (frontend shows it only in settings).

## Frontend conventions

- Page-per-folder pattern: `src/pages/<PageName>/PageName.jsx` with a matching `.css`; shared UI in `src/components/common/` (`Button`, `ConfirmModal`, `StatCard`, `UserAvatar`, `UserHandle`, `VerdictBadge`), layouts in `src/components/layout/` (`SharedNav` + `SearchBox` + `UserMenu`, `Footer`).
- Reviews are the most intricate page: `ReviewsPage` and `UserProfilePage` share `ReviewsPage.css`; verdicts render via color-coded classes (`filter-go-for-it`, etc. — class names are built with `replace(/_/g, '-')`, keep that normalization). **Every destructive action across the app goes through `ConfirmModal`** (no `window.confirm` anywhere). `BookDetailPage` renders verdicts with its own `.review-verdict` span + `.verdict-picker button.selected.*` rules (JSX emits lowercased, underscore-stripped verdict names).
- Self-review / edit-review rules (frontend + backend): a book's owner (`book.createdById === user.id`, `BookResponse` carries `createdById`) gets **no composer at all** on `BookDetailPage`; non-owners with an existing review see a "Your Review" card (verdict + message + `.review-edit-btn`) that swaps the composer into edit mode (`ReviewComposer` takes an optional `review` prop, submits via `updateReview`, heading/button become "Edit Review"/"Save changes"). Backend already enforces both rules server-side: `ReviewServiceImpl.create` blocks admin (403) and duplicate `userId+bookId` (409); owner self-review is blocked too — keep those guards if the UI changes. `reviewsApi.js` exports `createReview`/`updateReview`/`deleteReview`/`listMyReviews`.
- All API access goes through `src/services/apiClient.js` via per-domain modules in `src/services/` (`booksApi.js`, `authorsApi.js`, ...). `apiClient` injects the JWT from `localStorage` (`sv_token`, `sv_refresh_token` — keys must stay consistent), contains normalization shims for chapters and the admin dashboard payloads, and on 401 clears auth and redirects to `/login` unless the request targets an auth endpoint (`AUTH_PATHS`).
- Backend URL defaults to `http://localhost:8082/api`; override via `VITE_API_URL` (there is no Vite dev proxy). Only `.env.example` is committed — `.env`/`.env.production` exist on disk for local dev but are gitignored (also `VITE_APP_NAME`, `VITE_CLOUDINARY_*`).
- React Compiler is enabled via `vite.config.js` (`reactCompilerPreset` from `@vitejs/plugin-react`); keep it in mind when writing hook/memo patterns.
- Sticky page elements assume the `SharedNav` bar (72px desktop and mobile, `sticky top:0`); if you change the navbar height, re-check sticky offsets like the review cards at `top:90px`. The bar is a 3-zone grid (`auto 1fr auto 1fr auto`, named areas brand/nav/actions) that embeds `SearchBox` in the actions zone — desktop search hides below 800px, the mobile drawer gets its own variant.
- Mobile shell (below `max-width:800px`): `SharedNav` swaps the desktop bar for a 64px `.mobile-header` (brand left; right = search icon that expands a `.mobile-search-panel` with the debounced `SearchBox` + UserMenu avatar, or `.mobile-auth` login circle for guests). Navigation lives in a **floating glass dock** `BottomNav` (`src/components/layout/BottomNav/` — `BottomNav.jsx` + `NavItem.jsx` + `.css`): fixed 22px-radius pill (12px side margins, `bottom:10px + safe-area`, blur, soft elevation, 64px tall), 5 tabs with 48px targets. Regular: Explore/Genres/Leaderboard/Write/Profile; admin: Home/Explore/Authors/Profile/More. **Write (admin: Authors) is emphasized** — a violet-gradient pill raised `-4px` with glow. Icons are **lucide-react** (22px, stroke 1.8, 2.2 when active); active item gets a violet pill `motion layoutId="bnv-pill"` spring indicator + 1.12 icon scale, `whileTap` scale .96 (150ms); labels are 12px DM Sans medium, violet when active. No hamburger/drawer — deep links live in `UserMenu` (My Library/My Reviews/Settings/Admin). The nav adds `body.sv-shell`, which gets `padding-bottom:calc(96px + env(safe-area-inset-bottom,0px))` (rule lives in `BottomNav.css`); the header's search panel closes via `onNavigate`/`popstate` listener and a `resize` listener above 800px, and `.mobile-search-panel` is `display:none` by default so mobile state can't leak into the desktop bar (no setState-in-effect / ref-in-render — the flat ESLint config's `react-hooks` rules forbid both). `SearchBox` accepts optional `autoFocus` + `onNavigate` props (used by the mobile panel).
- Code splitting: `App.jsx` lazy-loads every page with `React.lazy` (Suspense fallback `.app-loading`); only `SharedNav`/`Footer`/services/store stay in the main chunk. Keep new page imports lazy.
- Global mobile baseline lives in `index.css` (`overflow-x:clip`, `-webkit-text-size-adjust:100%`, global `:focus-visible`) and `App.css` (`@media(max-width:640px)`: 48px touch targets for `.button`/`.button.ghost`/inputs, `border-radius:10px`, footer wrap, `.form-card{padding:22px}`). Pages keep their own breakpoints — the common ones are 1120/860 (reviews), 900/640 (landing), 800 (catalog/reader/chapters/editor), 760 (leaderboard), 700 (dashboards/settings/profile).
- Design tokens: `src/theme/tokens.css` (`--sv-bg:#000000` — the whole app background is **pure black**; panels `--sv-panel:#15131a`/`--sv-panel-2:#1b1822`, line `--sv-line:#302b38`, muted `--sv-muted:#958d9b`, cream `--sv-cream:#f4efe6`, accent violet `--sv-violet:#a98bd8`, coral `--sv-coral:#e87e72`, amber `--sv-amber:#e4aa63`, teal `--sv-teal:#71c3ad`). Keep new surfaces on these tokens — no stray near-blacks like `#0c0b0f`.
- `Footer` (`src/components/layout/Footer/Footer.css`) is a centered stack (brand/tagline/copyright), hairline border-top, subtle violet gradient wash, responsive size steps; content and routes unchanged.
- Login-page poster gallery: `src/components/common/PosterGallery/` (`PosterGallery.jsx` + `PosterCard.jsx` + `PosterSkeleton.jsx` + `.css`) fills the left 65% of `LoginPage` (`.login-art`) with a staggered **CSS multi-column** (5→4→3 cols via media queries) wall of 2:3 poster cards fetched live via `listBooks('?size=48&sort=createdAt,desc')` (plain JS + CSS, no Tailwind/TS — repo convention; poster `coverImage`/`thumbnailUrl` fallback, else a "SV" monogram placeholder). Framer-motion float (`y: [0,-7,0]`, 6–9.6s easeInOut, per-index delay), `whileHover` scale 1.04 (200ms) + brightness/shadow via CSS, hover caption with title/genre, slight `:nth-child` rotations, shimmer skeletons, IntersectionObserver defers offscreen renders + `loading="lazy"`. `.login-overlay` (z-1) fades the gallery into black toward the form (radial violet glow + noise `::after` at z-2); below 800px the gallery is hidden and a `.mobile-brand` wordmark shows in the form panel. Poster width is derived from the 65fr/35fr grid — don't hardcode 140–180px.
- Search: `SearchBox` (in `SharedNav/`) debounces ~250ms against `GET /api/books?q=<term>` and shows a dropdown of top results; Enter submits to `/search?q=…`. The `/search` route renders `ExplorePage` — `?q=` shows a search-results grid, `?view=` shows an All-Books grid for that section.
- Explore page carousels are native flex rows (wheel-to-horizontal with end guards, pointer drag, scroll-snap, hidden scrollbars) — NOT swiper; cards are 200×400 with a 78/22 poster/info split and a 2-line-clamped title. Swiper (`FreeMode`) is used only by `LandingPage` for the trending shelf.
- `LandingPage` hero shows a "review meter" explainer card whose 4 verdict colors must stay aligned with the `Meter` component in `BookDetailPage` (`SKIP #FF5F7D, TIMEPASS #F4B400, GO_FOR_IT #00D084, PERFECTION #A855F7`).
- Review meter: `BookDetailPage` renders the animated `MoctaleMeter` (`src/components/review-meter/` — `MoctaleMeter.jsx` + `.css`, `MeterArc.jsx`, `MeterCenter.jsx`, `MeterLegend.jsx`, `useMeterCalculation.js`, `meterUtils.js`, `constants.js`). `constants.js` owns the verdict keys/colors (`VERDICT_LABELS`, `VERDICT_COLORS`, `CATEGORIES`) plus `METER` geometry (viewBox `0 0 400 230`, cx/cy 200, radius 170, stroke 22, 180° sweep, 10° gap, 700ms easeInOut). Arcs render at their final state immediately on mount (`initial={false}` — no entrance animation) and re-animate on data/hover changes; 0% categories render **no arc** (`buildSegments` filters them out and redistributes the gaps, so e.g. a 100% category fills the full semicircle); hover adds a glow (`drop-shadow`) + thicker stroke and dims others to 40% — the glow is hover-only, while click-lock (`selected`) keeps the thicker-stroke emphasis without the glow. It replaces only the non-compact usage; the compact `Meter` export in `BookDetailPage.jsx` is still used by `LeaderboardPage` (`compact` prop, viewBox `0 0 200 115`), so keep that export and its base `.meter-*` CSS.
- Profile socials: `src/utils/socials.js` `socialLinks(user)` turns `instagram`/`twitter`/`youtube` strings into links with feather brand icons (prepends `https://instagram.com/`/`https://x.com/` when the value isn't a full URL, strips a leading `@`); rendered as round icon buttons (`.review-socials` in `ReviewsPage`/`UserProfilePage` profile cards, `.profile-socials` in `ProfilePage`). `SettingsPage` posts them (plus `dateOfBirth`, bio, name, optional new image) via `updateMe` and syncs the Redux user via `setUser`.
- Chapter editing uses Lexical: `src/components/rich-editor/RichTextEditor.jsx` + `.css` (toolbar for bold/italic/underline/strikethrough, H1–H3, quote, bullet/numbered lists, undo/redo, clear). It persists **HTML** (`$generateHtmlFromNodes`) and seeds its state from HTML or legacy plain text (`seedEditor` via DOMParser). `ReaderPage` renders HTML chapters via `dangerouslySetInnerHTML` (`.prose` styles) and falls back to the old `\n`-split paragraphs for legacy chapters (`looksLikeHtml` check). Reader themes: `ReaderPage` emits `reader-${theme}` classes (`reader-dark`/`reader-light`/`reader-sepia` — CSS must use `.reader.reader-dark` etc., NOT `.reader.dark`), each theme sets `--reader-ink`/`--reader-mute`/`--reader-accent`/`--reader-hairline` CSS vars that all reader UI (bar, chapter index, prose, dropcap, nav) must consume instead of the global tokens — that keeps text readable on light/sepia backgrounds. `ChaptersPage` chapter-number input defaults to max + 1 but is **editable** (reorder chapters by changing numbers; coerced to int in the `set` handler); word counts use `plainWords` (tag-stripping regex). The studio layout is a 1fr/3fr grid (chapter list 25%, editor 75%).
- Access token lifetime: `app.security.jwt.access-minutes` defaults to **1440 (24h)** — env-overridable via `JWT_ACCESS_MINUTES`; refresh tokens live 7 days (`AuthServiceImpl`).
